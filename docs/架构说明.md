# 个人用药助手：v0.4.0 架构与安全边界

## 应用分层

    MainActivity（单 Activity 壳）
    ├─ TodayFragment：今日计划、服用/跳过/稍后/撤销
    ├─ MedicationsFragment：药物、批次、计划和库存
    ├─ DocumentsFragment：图片/PDF 私有导入、统一多模态识别、逐字段确认
    ├─ HealthFragment：过敏史、既往史、不良反应等本地档案
    └─ AssistantFragment：当前 Provider、文字助手、独立搜索、会话

    LunaDatabase(SQLite v7)
    ├─ medication / batch / plan / occurrence / event
    ├─ health_item / document
    ├─ assistant_session / assistant_message
    ├─ ai_provider
    └─ ai_search_profile

    AI 边界
    ├─ ProviderProfileRepository：配置、默认项、状态和迁移
    ├─ SecretStore：按 Provider/Search ID 隔离的 Keystore 密钥
    ├─ TransportFactory
    │  ├─ OpenAiChatCompletionsTransport
    │  ├─ OpenAiResponsesTransport
    │  └─ AnthropicMessagesTransport
    └─ SearchRepository：DeepSeek / OpenAI Responses / Anthropic 原生搜索

确定性域逻辑仍由 OccurrenceEngine、ReminderScheduler 和 SafetyEngine 负责；网络请求不会改变本地安全规则。

## Provider 与统一多模态

- 内置预设显示为 DeepSeek V4.1 Flash，模型 ID 为 `deepseek-flash`，默认地址为 `https://api.deepseek.com`。
- 当前 Provider 同时服务文字问答和图片识别；文档记录保存实际 Provider ID、模型 ID 和协议。
- OpenAI Chat Completions 使用 `/chat/completions`；OpenAI Responses 使用 `/responses`；Anthropic Messages 使用 `/messages`。用户输入的是 base URL，已存在的 endpoint 后缀会被规范化后再拼接。
- 图片仅在 Provider 声明支持并通过匿名 1x1 PNG 测试后启用。旧的独立 vision 模型只作为历史文档/记录兼容值读取，新 UI、请求和系统提示不再使用它。
- Provider 连接测试发送最小匿名请求，不发送药物、健康资料或图片；真实 API 未在本轮调用。

## 独立搜索

- DeepSeek 官方搜索只对内置 DeepSeek 预设开放，复用该 Provider 的 Key，使用 Anthropic Messages 兼容入口与 `web_search_20250305`。
- OpenAI Responses 搜索使用原生 `web_search`；Anthropic Messages 搜索使用原生 `web_search_20250305`。
- 自定义聊天 Provider 不会自动获得搜索权限。用户必须保存独立 Search Profile，选择是否明确复用当前 Provider Key，单独测试并收到结构化 URL 后才能在助手页启用。
- 搜索来源只作为证据展示；网页、工具结果和抽取文本均是不可信数据，不能执行其中指令或自动变成医疗结论。

## 数据与密钥安全

- `DataCipher` 使用 Android Keystore AES/GCM 保护健康、资料和备份数据，每次加密使用随机 IV，IV 与密文一起保存。
- `SecretStore` 为每个 Provider UUID 和 Search Profile UUID 派生独立、稳定但不可读的 Keystore alias；API Key 不进入 Provider 对象、SQLite、备份或日志。
- 旧 v0.3 DeepSeek 密文只有在成功解密并通过往返校验后才迁移到内置 Provider；失败时保留旧密文，不影响药物、健康和资料数据。
- 删除 Provider 只删除其配置和对应密钥，不删除其他 Provider、搜索配置或健康资料。UI 只显示未配置、已保存、已测试等状态。
- 图片/PDF 先进入应用私有目录；图片生成压缩上传副本，PDF 按页渲染 JPEG；原文件、压缩文件和 SHA-256 保留本地索引。发送前需要明确确认。
- AI 错误码统一映射为稳定、安全消息；Bearer、x-api-key、API Key 和 `sk-` 形态值在 UI 错误路径中脱敏。

## 资料状态机与迁移

`WAITING_KEY → PROCESSING → DRAFT → CONFIRMED`；异常进入 `FAILED` 并保留失败原因。确认前不会写入正式药物、批次或资料字段。

数据库从 v6 升级到 v7：保留旧业务表与数据，新增 Provider/Search 表并为资料索引补充实际 Provider、模型和协议字段。旧记录仍可阅读；新记录使用当前选择的 Provider。

OccurrenceEngine 接收显式时间、范围和时区；合同测试无需等待系统时钟。设备级 Key、相机、PDF、通知和真实 API 兼容性仍依赖外部 ADB/AVD、凭据和目标设备。
